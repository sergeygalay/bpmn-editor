# BPMN Editor

Онлайн-редактор BPMN 2.0 на базе [bpmn-js](https://bpmn.io/toolkit/bpmn-js/) с хранением диаграмм в GitHub.

## Онлайн-редактор

`https://sergeygalay.github.io/bpmn-editor/`

Прямая ссылка на конкретную диаграмму:

`https://sergeygalay.github.io/bpmn-editor/?diagram=<id>`

Например:

`https://sergeygalay.github.io/bpmn-editor/?diagram=shop`

## Где хранятся диаграммы

Все BPMN-модели находятся в:

`diagrams/*.bpmn`

Каталог диаграмм:

`diagrams/index.json`

Каталог содержит стабильный `id`, отображаемое имя, путь, группу и описание. Перед созданием, поиском, изменением или удалением диаграммы нужно сначала читать `diagrams/index.json`.

## Работа с ChatGPT

Репозиторий содержит `AGENTS.md` — контракт для AI, описывающий правила создания, просмотра, изменения и удаления BPMN 2.0 диаграмм.

В новом чате достаточно указать репозиторий `sergeygalay/bpmn-editor` и попросить прочитать `AGENTS.md`. После этого нормальный рабочий процесс должен быть таким:

1. ChatGPT читает `diagrams/index.json`.
2. Находит или создаёт нужную BPMN-диаграмму.
3. Работает с корректным BPMN 2.0 XML и BPMN DI.
4. Сохраняет изменения в GitHub.
5. Возвращает прямую ссылку на диаграмму в онлайн-редакторе.

Ручное скачивание и импорт `.bpmn` не являются стандартным workflow этого репозитория.

## Рекомендуемый ChatGPT Project

Чтобы новые чаты сразу знали, как работать с диаграммами, создайте ChatGPT Project, например `BPMN`, и добавьте в Project Instructions этот текст:

```text
Для BPMN-задач используй GitHub-репозиторий sergeygalay/bpmn-editor как источник истины.

В начале BPMN-задачи прочитай AGENTS.md и diagrams/index.json из этого репозитория и следуй описанному там workflow.

Все диаграммы хранятся в diagrams/*.bpmn, каталог — diagrams/index.json.

Создавай и изменяй настоящий BPMN 2.0 XML с BPMN DI. Предпочитай корректную BPMN-семантику: pools, lanes, sequence flows, message flows, events, tasks, gateways, subprocesses и boundary events по смыслу.

После создания или изменения сохраняй результат непосредственно в GitHub и возвращай прямую ссылку:
https://sergeygalay.github.io/bpmn-editor/?diagram=<id>

Не предлагай скачивание/ручной импорт .bpmn и не подменяй BPMN обычной блок-схемой, если я явно этого не просил.
```

## Создание новой диаграммы

Минимальный workflow:

1. Прочитать `diagrams/index.json`.
2. Выбрать стабильный `id`, например `vacation-request`.
3. Создать `diagrams/vacation-request.bpmn`.
4. Добавить BPMN DI, чтобы модель сразу отображалась в bpmn-js.
5. Добавить запись в `diagrams/index.json`.
6. Открыть:

`https://sergeygalay.github.io/bpmn-editor/?diagram=vacation-request`

## Изменение существующей диаграммы

Перед изменением всегда нужно прочитать текущий `.bpmn` из GitHub. Это важно, потому что пользователь может сохранить изменения непосредственно из браузерного редактора, и версия в репозитории может быть новее контекста предыдущего чата.

После редактирования следует сохранять полный BPMN XML обратно в тот же файл, сохраняя существующие ID элементов там, где бизнес-смысл элемента не изменился.

## Семантика BPMN

Основные правила описаны в `AGENTS.md`. В частности:

- lanes — роли внутри одного participant/process;
- pools — независимые участники;
- sequence flow не пересекает границы pools;
- message flow используется между pools;
- BPMN DI обязателен для моделей, которые должны сразу отображаться в онлайн-редакторе.

## Сохранение из браузера

Редактор поддерживает сохранение пользовательских изменений обратно в GitHub через GitHub API. Учетные данные/токены не должны храниться в репозитории или передаваться в ChatGPT.

## GitHub Pages

Публикация настроена из ветки `main`, корень `/`.

Основные файлы веб-приложения:

- `index.html`
- `app.js`
- `styles.css`
- `.nojekyll`

Изменения этих файлов автоматически попадают в GitHub Pages после очередного deployment.
